# Windows Shell Safety Plugin

## Summary

`windows-shell-safety` keeps agents from wasting time on Windows when Azure CLI, JSON payloads, and pipelines lose characters on the way to a native command. The skill prescribes one safe execution path, a bundled lint flags broken command shapes before they run, and a PowerShell 7 helper implements the safe path. Tracking: parent issue #84 with sub-issues #85-#88.

## Design

- `az` on Windows is the batch file `az.cmd`, so its arguments are parsed by PowerShell and then by `cmd.exe`. PowerShell 7.3+ keeps legacy argument passing for `.cmd`/`.bat` targets (quotes only around arguments with whitespace, embedded `"` not escaped), and `cmd.exe` consumes unquoted `|`, `&`, `<`, `>`, `^` and expands `%NAME%` even inside quotes. The same applies to other batch shims (`npm`, `npx`, `pnpm`, `yarn`, `code`, `func`, `ng`); `.exe` tools such as `gh` and `git` are not affected.
- Rules, in priority order: use `pwsh` only; run scripts with `pwsh -File`, never a `-Command` string; never put JSON in an argument (UTF-8 no-BOM file passed as a quoted `'@<file>'`); keep `cmd` metacharacters and quotes out of `az` arguments by filtering with `ConvertFrom-Json` or loading `--query` from `'@<file>'` (az accepts `@<file>` for any argument); force UTF-8 console encoding and `PYTHONIOENCODING=utf-8` before parsing native output; lint before running; inspect received argv before changing escaping.
- `Test-NativeCommand.ps1` accepts `-Command`, `-Path`, or pipeline input, parses PowerShell with the language AST, and adds line rules that also work on Bash command lines; the line rules ignore comments and message strings. Rules: WSS001 any `cmd`/`cmd.exe` invocation or `%COMSPEC%`, WSS002 `-Command` strings with pipes, quotes, or braces, WSS003 `cmd` metacharacters in batch-target arguments (including string variables), WSS004 inline JSON (literal, `ConvertTo-Json` result, or variable), WSS005 embedded double quotes, WSS006 Windows PowerShell 5.1, WSS007 native output parsed as JSON without a UTF-8 setting earlier in the same or an enclosing block (warning), WSS008 MSYS workarounds, WSS009 unquoted `@file` splatting. Exit code 0 clean, 1 findings, 2 missing file; `-AsJson` for machine output.
- `Invoke-NativeJson.ps1` is dot-sourced. `Invoke-NativeJson` sets UTF-8 encodings for the call, writes `-Body` to a UTF-8 temporary file referenced as `@<file>` (format configurable, e.g. `gh api --input <file>`), refuses `cmd`-rewritable arguments for batch targets before running, throws with stderr on failure, parses JSON output, and cleans up. `Invoke-AzJson` adds `-o json` and `PYTHONIOENCODING`, and rejects a non-JSON `-o`/`--output` unless `-Raw` is given. `-EchoArgs` on either function prints the argv the target would receive, body file included, instead of running it. `Show-NativeArgs` prints the argv a child receives through a `.cmd` shim that forwards `%*` like `az.cmd`.
- No PreToolUse hook: the lint is advisory so a false positive never blocks work. Azure DevOps skills link to this skill instead of duplicating its rules.

## Verification

- `python3 scripts/validate_marketplaces.py` validates the plugin metadata and links.
- `tests/test_native_command_lint.py` (unittest through `pwsh`) checks that every unsafe fixture reports its rule, every rule WSS001-WSS009 has a fixture, safe fixtures are clean, command/pipeline/path inputs and exit codes, and the helper's UTF-8 body round trip, batch refusal, stderr reporting, and argv echo. It runs in the existing Ubuntu test job.
- `tests/Invoke-WindowsRepro.ps1` runs in the `windows-latest` CI job: it confirms `az` resolves to `az.cmd`, shows a `.cmd` shim losing `a|b`, `a&b`, inline JSON, and `%USERNAME%`, shows `az version --query` breaking with an unquoted pipe or embedded quotes, and verifies that `--query '@<file>'`, `ConvertFrom-Json` filtering, the helper's refusal, and the lint behave as documented. `az version` needs no sign-in.

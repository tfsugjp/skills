# .NET / Azure 教訓プラグイン

## 概要

`dotnet-azure-lessons` は、エージェントセッションで実際に受けた訂正を、.NET・Azure・PowerShell 向けの適用範囲が明確で確認可能な指針にします。11 個のスキルと読み取り専用レビューエージェントで構成します。追跡: 親 Issue #107、子 Issue #108–#111。

## 設計

- 実際の失敗、ユーザーの訂正、レビュー指摘から教訓を選びます。未実行の提案や静的な指摘はその状態を区別します。識別情報は一般化し、生の履歴、資格情報、非公開パス、プロジェクト固有の前提を公開しません。
- description は発動するタスクや症状を短く具体的に示します。関連するルールと参照先だけを読み込みます。11 個の入口を維持し、今回の履歴を分類するためだけのスキルは増やしません。
- 自明でない不変条件には、簡潔なルール、観測可能な確認方法、失敗の理由を残します。繰り返しの体験談、一般的な心構え、重複する末尾チェックリスト、重なる手順は削除します。共通ルールの所有先を一つにし、見出し名で相互参照します。
- 適用条件と例外を明記します。ルール自体を、外部更新、インストール、資格情報の初期化、設定変更、無関係なウィンドウの終了、依頼範囲拡大の許可にはしません。既存の許可を再利用し、現在のセッションの権限機構に従い、承認要求と明示的な拒否を区別します。コマンドの先頭一致に関する助言は、そのポリシーがある環境だけに適用します。
- 根拠のある不足点を補います。投稿前に現在の PR head で指摘を再評価すること、CLI 認証と Git 資格情報ヘルパーを区別すること、環境・プロファイル更新を候補領域で検証してから切り替え、管理外データを保護し、部分失敗からの復旧を定義すること、PowerShell ソースと生成ファイルのエンコーディング要件を区別することです。
- 技術的な再発防止ルールを維持しながら、一律の要求を限定します。ソリューション形式の移行は依頼範囲内とし、パッケージのインストールと UI 検証は適切な許可済み環境で行い、前提条件の不成立と回復可能な警告、安全なパッケージビルドと資格情報を使う公開を区別します。技術的な意味を変える場合は正本で再確認します。
- レビューエージェントはコミット済み・ステージ済み・未ステージの変更を対象とし、該当する確認方法を選び、修正可能な欠陥と証拠の不足を分けて報告します。未提供のスクリーンショットや未実行の OS テストを欠陥の証明とせず、外部記録を変更しません。
- 専門手順は既存の `windows-shell-safety`、`github-pull-request`、`github-plan-issues`、`azure-devops-pipelines`、`project-documentation`、`nuget-validate`、`native-container-cli` が所有します。任意のスキルが利用できなくても、その手順を実行したと報告しません。

| スキル | 工程または状況 |
|---|---|
| `dotnet-architecture-design` | 設計書、ADR、対応バージョン |
| `dotnet-coding` | C# の実装 |
| `vs-extension-remote-ui` | Visual Studio Remote UI の ViewModel と XAML |
| `powershell-scripting` | PowerShell スクリプト |
| `dotnet-debugging` | 障害の調査 |
| `dotnet-testing` | テストと、変更が検証済みかの判断 |
| `dotnet-documentation` | コードとともに変わる文書 |
| `dotnet-ci-cd` | ワークフローとパイプラインの定義、パッケージング |
| `pr-issue-workflow` | レビュースレッド、コミット、push、マージ、Issue のクローズ |
| `dotnet-macos-development` | macOS や Apple silicon での .NET / Azure の作業 |
| `agent-sandbox-troubleshooting` | エージェントセッションの sandbox、権限、資格情報が原因でコマンドが失敗したとき |

## 検証

- マーケットプレースのマニフェスト、frontmatter、名前、相対リンクを検証し、最終差分と日英の整合性を確認します。
- 抽出元の識別情報や秘密情報がプラグインに混入していないか確認します。履歴の根拠はローカルに保ち、元セッションの抜粋を公開しません。
- PR head の変更、認証失敗、拒否された操作、ステージ済み変更、プロファイル更新の部分失敗、利用できない環境での検証について、独立した読み取り専用のシナリオ評価を行います。文言の一致ではなく判断と副作用を確認します。
- 静的検証、模擬シナリオの結果、実クライアントでのスキル選択を区別します。観測していない実際の発動や OS 上での実行を確認済みと報告しません。
